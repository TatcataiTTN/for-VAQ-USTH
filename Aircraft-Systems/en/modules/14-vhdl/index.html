PART 1/3
01

An HDL describes a large circuit formally and simulably; VHDL separates the entity (interface) from the architecture (behaviour)

  • Why an HDL
  • Entity and architecture: the half adder

A logic system of hundreds of thousands of elements cannot be described with truth tables, so a hardware description language (HDL) is needed

(Tooley 17.1.) LSI/VLSI systems in avionic equipment usually sit on one silicon chip with hundreds of thousands of elements. Four problems: the logic must be simulated, tested and verified before manufacture; it must be described clearly and unambiguously; it must respect the speed limits and propagation delays of the elements; and components must be reusable. Truth tables, diagrams and Boolean algebra become cumbersome, error-prone and cannot express delay. An HDL lets the designer model a device, simulate it and refine it before committing to hardware. Verilog appeared in 1985; two years later, at the request of the US Department of Defense for very high-speed integrated circuits (VHSIC), came VHDL.

📖 Explanation for beginners

VHDL and Verilog dominate digital design tools. An HDL is not a general-purpose programming language like C++: it describes logic by function, data flow and behaviour.

The entity declares the interface with PORT, the architecture describes the behaviour; a half adder has sum = x XOR y and carry = x AND y

(Tooley 17.2, 17.3.) An entity must be declared before use: a unique name and its input and output ports. The architecture defines the behaviour. The code below has corrected syntax (the book prints a semicolon in the sensitivity list and a few other misprints):

ENTITY half_adder IS
  PORT (x, y : IN bit;
        sum, carry : OUT bit);
END half_adder;

ARCHITECTURE half_adder_behaviour OF half_adder IS
BEGIN
  PROCESS (x, y)
  BEGIN
    sum   <= x XOR y;
    carry <= x AND y;
  END PROCESS;
END half_adder_behaviour;

Adding an active-high enable EN: with EN = 1 it works normally, with EN = 0 both outputs are 0, using IF ... THEN ... ELSE ... END IF:

ARCHITECTURE half_adder_behaviour OF half_adder IS
BEGIN
  PROCESS (x, y, en)
  BEGIN
    IF en = '1' THEN
      sum   <= x XOR y;
      carry <= x AND y;
    ELSE
      sum   <= '0';
      carry <= '0';
    END IF;
  END PROCESS;
END half_adder_behaviour;
📖 Explanation for beginners

The entity is a "wrapper" hiding the inside: you only need to know what it does and how to connect it. So an entity that has been designed and tested can be reused in many systems. The site checked the truth table two ways (XOR/AND and arithmetic addition): they agree.

PART 2/3
02

The VHDL design flow has seven stages; signals have modes and types, and operators have precedence

  • The seven stages of the design flow
  • Signal modes, data types and operators
  • Describing a D bistable with IF

The VHDL design flow runs from conception to verification in seven stages, with simulation before synthesis

#StageMain task
1Conceptionneeds analysis, detailed specification, list of interface signals
2Codingwrite each component, choose libraries and reusable code
3Compilationcheck syntax errors and compatibility between modules
4Simulationapply inputs with a test bench, check outputs, test delays
5Synthesisconvert to target-technology components; an ASIC exports a net list
6Fitting, placement, routingphysical realisation in hardware
7Verificationtest on the real avionics platform, to the temperature and voltage limits

(Tooley 17.4.) Floyd 10-5 describes the same idea for programmable devices (Module 11).

📖 Explanation for beginners

Exam tip: "Which comes earlier: simulation, coding or verification?" The answer is coding (Tooley Chapter 17 Q7).

Signals have modes IN, OUT, BUFFER, INOUT and types bit, bit_vector, std_logic; NOT binds tighter than shifts, shifts tighter than AND/OR

  • IN: input. OUT: output, only visible from outside. BUFFER: output that can also be read inside. INOUT: input or output (a tri-state line).
  • Types: bit (0, 1), bit_vector, std_logic with nine values U, X, 0, 1, Z, W, L, H, "-" (defined in the IEEE library; U = uninitialised), std_logic_vector; Boolean is a type, while IN and BUFFER are modes.
  • The signal assignment operator is <=; a comment starts with two hyphens.

The values in the table match Tooley's examples in 17.7 (0010, 0100, 1000, 1000, 0001); the site recomputed them two ways (4-bit integers and bit strings) for all 256 pairs (p, q). SLA is used here only on vectors whose right-most bit is 0 because the book does not define the bit shifted in.

A D bistable described with IF: the asynchronous clear has priority, and data enters only at the rising clock edge

(Tooley 17.8.) Corrected code (the book prints ELSEIF for ELSIF and a few other misprints):

LIBRARY ieee;
USE ieee.std_logic_1164.ALL;
ENTITY d_bistable IS
  PORT (clk, clr, d : IN std_logic;
        q : OUT std_logic);
END d_bistable;

ARCHITECTURE d_bistable_behaviour OF d_bistable IS
BEGIN
  PROCESS (clk, clr)
  BEGIN
    IF clr = '1' THEN
      q <= '0';
    ELSIF clk'EVENT AND clk = '1' THEN
      q <= d;
    END IF;
  END PROCESS;
END d_bistable_behaviour;

If clr = '1' then q goes to 0; otherwise at the rising edge of clk q <= d. For a multi-bit register use vectors: d : IN std_logic_vector(3 DOWNTO 0) (the book prints "3 down to 0").

📖 Explanation for beginners

Compare Module 11: this is exactly the D flip-flop with an asynchronous clear; only the description differs (code instead of a diagram). Inside a PROCESS statements run sequentially, but PROCESSes run concurrently with each other.

PART 3/3
03

A test bench simulates the component before manufacture, and a gate_delay constant models the delay that causes spurious states in fast circuits

  • Simulation and the test bench
  • Modelling propagation delay

A test bench is separate event-driven code that applies input waveforms to the component, and an HDL must handle many parallel processes

(Tooley 17.9.) Simulation establishes the performance of an HDL model under many conditions. A test bench is written separately from the component declaration and defines precisely all signals and clock waveforms; the code is event-driven so events occur exactly when the test bench says. The simulator shows signals against time and lets you halt at breakpoints. The key difference from ordinary programming languages: procedural languages are single-threaded, while an HDL must model many parallel processes that may happen at the same instant, so an HDL is concurrent, multi-threaded. The book's example simulates the APU starter logic of Chapter 5 with three inputs (apu_start, apu_shutdown, apu_running) and one output (apu_starter).

📖 Explanation for beginners

Simulation lets a logic design pass design verification before manufacture and download: a fault found here is far cheaper than one found in hardware.

Propagation delay is modelled with a gate_delay constant: a three-gate half adder of 15 ns gates delays the Sum output by 45 ns

(Tooley 17.10.) VHDL accurately models the delays inherent in real devices. The timing diagram of a half adder built from standard gates (7408, 7404, 7408, about 15 ns each) shows the Sum output 45 ns behind a change at Input A. At low speed the delay is tolerable, but at high speed the finite time for a logic level to reach the output can produce spurious transient logic states with unpredictable effects. The model of a 15 ns XOR gate:

ARCHITECTURE dataflow OF xor_gate IS
  CONSTANT gate_delay : time := 15 ns;
BEGIN
  c <= (a XOR b) AFTER gate_delay;
END ARCHITECTURE;
Path delay through n gates
$$T_{path}=n\,t_{gate}\qquad(n=3,\;t_{gate}=15\text{ ns}\Rightarrow 45\text{ ns})$$
📖 Explanation for beginners

The same idea as the ripple counter in Module 11: the delays add up as $n\times t_{pd}$ and set the maximum frequency. VHDL lets you measure this in simulation.

Detailed notes

Five worked examples

Example · Example 1: an expression by precedence (Tooley)

$p=1010$, $q=0110$: NOT p AND q = (NOT p) AND q = 0101 AND 0110 = 0100.

Result (checked by program): 0100

Example · Example 2: Tooley Chapter 17 Q12

$x=101$, $y=011$: not x and y = (010) AND 011 = 010.

Result (checked by program): 010

Example · Example 3: Test Your Understanding 17.5

$x=0011$, $y=0100$: x AND y = 0000; NOT x OR NOT y = 1100 OR 1011 = 1111.

Result (checked by program): 0000; 1111

Example · Example 4: the half adder with EN

$x=1$, $y=1$: EN = 1 gives (sum, carry) = (0, 1); EN = 0 gives (0, 0).

Result (checked by program): (0, 1); (0, 0)

Example · Example 5: signal path delay

Three 15 ns gates: $3\times15=45$ ns; five 12 ns gates: 60 ns.

Result (checked by program): 45 ns; 60 ns

Points to note in the sources
  • The VHDL code printed in Tooley Chapter 17 has several misprints (OCR and book): "PROCESS (x; y)" needs commas, "ELSEIF" must be "ELSIF", "3 down to 0" must be "3 DOWNTO 0", "half-adder" at END must be "half_adder", and "dad" is "d". The module uses the corrected syntax; it has NOT been compiled with a real VHDL tool.
  • Tooley's "p AND SLA q" writes SLA as a unary one-place shift; in standard VHDL SLA is binary (q SLA 1) and fills with the right-most bit. The site uses SLA only on vectors whose right-most bit is 0 (then SLA equals SLL).

Source errors and doubts

  • The VHDL code printed in Tooley Chapter 17 has several misprints: "PROCESS (x; y)" needs commas, "ELSEIF" must be "ELSIF", "3 down to 0" must be "3 DOWNTO 0", "half-adder" at END must be "half_adder", "dad" is "d". The module uses corrected syntax. The code has NOT been compiled with a real VHDL tool (not done); the calculations (operators, truth tables, delays) were checked.
  • Tooley 17.7 writes "p AND SLA q" with SLA as a unary one-place shift; in standard VHDL SLA is binary (q SLA 1) and fills the vacated place with the right-most bit. The site uses SLA only on vectors whose right-most bit is 0, where SLA equals SLL and the results match the book.
  • Test Your Understanding 17.5 asks "SLA p AND NOT q" with p = 0011: the right-most bit is 1 so SLA fills with 1 (0111) by the standard, while a plain shift gives 0110; the book gives no answer and the site does not put this one in the bank.
