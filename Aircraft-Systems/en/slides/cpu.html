Slide 3: Computer system: the IPO principle

Input, process, output. Input: data or instructions entered through input devices (keyboard, mouse, microphone, scanner, a sensor such as one on an aircraft); examples: type the number 25, type the instruction 25 + 10, enter data from a sensor. Process: the computer processes the data according to the program; the CPU (microprocessor) performs arithmetic, logic and control operations inside the system unit with memory (RAM) and storage (SSD/HDD); examples: the CPU calculates 25 + 10, compares data, executes program instructions. Output: the result is sent to output devices (monitor showing 35, printer, speaker); examples: display the result 35, print a document, play a sound, send a control signal to another system such as an actuator in an aircraft. Feedback: the user receives the result and may provide new input.

Slide 4: IPO principle in the Airbus A320 computer system

Input: data from sensors and pilot inputs: air data sensors (airspeed, altitude, outside air temperature); engine sensors (N1 and N2 speed, EGT, fuel flow, pressure); pilot inputs (thrust lever position, flight control inputs, switches such as flap and gear); other sensors (flap position, landing gear position, weight on wheels, cabin pressure). Process: the A320 flight control computer (FCC) processes the data according to the program: the CPU (microprocessor) executes flight control laws, performs calculations, monitors systems and detects failures; memory stores programs (software) and data (for example parameters); input/output interfaces communicate with sensors and actuators and exchange data with other computers (for example FMGC, ECAM). Output: to actuators, control signals to servo actuators that move the aileron, elevator and rudder; to the cockpit, information on the PFD (attitude, speed, altitude), ND (navigation information) and ECAM (engine and system status). Feedback: new data is continuously provided to the computer.

Slide 5: Computer system: components and an example

A computer system is a set of integrated devices that input, output, process and store data and information. Input devices (keyboard, mouse, scanner, microphone) enter data. The central processing unit (CPU) processes data according to the program and contains the control unit (CU, controls the operation of the computer and coordinates all parts), the arithmetic logic unit (ALU, arithmetic and logic operations such as 25 + 10 = 35) and registers (temporary data storage inside the CPU). Main memory (RAM) temporarily stores data and programs while running and loses data when power is off. Secondary storage (SSD, hard disk) permanently stores data, programs and files and keeps data when power is off. Output devices (monitor, printer, speakers) present the results. Example 25 + 10: 1 type 25 + 10 on the keyboard (input); 2 the data goes to the CPU; 3 the CPU computes 25 + 10 = 35; 4 the result 35 goes to the monitor (output); 5 if saved, the result is stored in storage (SSD/HDD). Summary: computer system = input + process + output + storage.

Slide 6: Computer system: hardware and software

A computer system has two complementary parts, hardware and software. Hardware (physical parts you can touch): aircraft computer (LRU, for example the flight control computer), microprocessor (CPU), memory, sensors, circuit boards, wiring and connectors, cockpit displays (PFD/ND), actuators (servo motors). Software (instructions and information): program instructions (control laws, system logic, fault detection; a pseudo-code sample "IF ALT < 100 THEN MODE = FLARE ELSE MODE = NORMAL"), data tables and parameters (configuration data, calibration values, limits; a sample table with flare height 100 ft, pitch limit 15 deg, roll limit 30 deg), algorithms and calculations (filtering, comparison, redundancy), operating system and support software (task management, I/O, communication, built-in test). Software controls hardware and hardware executes software. A320 example: pilot inputs and sensor data go to an aircraft computer (hardware plus software) which sends output commands to displays and actuators: input, process, output, store. Closing line: hardware is what the computer is; software is what the computer does.

Slide 7: Input device: the keyboard

A keyboard is a typewriter-style device using an arrangement of buttons or keys that act as mechanical levers or electronic switches. 1 External view: key caps. 2 Inside a key (mechanical switch): key cap, plunger (moves down when pressed), spring (returns the key), contacts (close when pressed). 3 Keyboard matrix: keys arranged in rows and columns; each key corresponds to a switch at the intersection of one row and one column (rows 1 to 4, columns 1 to 3, keys 1 to 9, *, 0, #). 4 Detecting a press: pressing key 5 closes the switch at row 2, column 2. 5 Signal to the computer: the keyboard controller scans the matrix, detects the pressed key and converts it to a digital code (scan code, for example 0x2D); the computer (operating system) receives the scan code, interprets it as the character 5 and passes it to the application (for example a text editor). Summary: the controller detects the row and column, converts it to a code and sends it to the computer as input data.

Slide 8: Operating principle of a computer mouse

A. Mechanical mouse with a rubber ball: the ball rolls when the mouse moves and turns the X-axis and Y-axis motion detection wheels (with encoders); the circuit counts the rotations to find the distance and direction of movement (X, Y). B. Optical mouse with an optical sensor: an LED illuminates the surface; a lens and image sensor capture many consecutive images; the mouse controller (processor) compares images at time t and t+1 to calculate how far and in which direction the mouse moved (delta X, delta Y). Chain: mouse movement (delta X, delta Y), the controller converts it to electrical/digital signals, the computer receives and processes the data, the display moves the cursor. A mouse is an input device because it sends information about the user's movements and actions to the computer.

Slide 10: Output device: the printer

A printer is a peripheral device that makes a persistent representation of graphics or text on paper. Block diagram: digital data from the computer goes to the printer driver (software; converts data to printer commands and controls printing), then the printer hardware (controller, print engine (laser or ink), paper handling mechanism), then the printed output on paper. Common types: laser printer (laser and toner; fast and high quality; common in offices), inkjet printer (sprays liquid ink; good for colour printing; common at home), dot-matrix printer (pins strike an ink ribbon; often used for multi-part forms such as invoices). Example outputs: text document, data and charts, images and graphics. Key points: a printer is an output device; it turns digital data into a permanent hard copy on paper; common types are laser, inkjet and dot-matrix; used for documents, reports, images and graphics.

Slide 11: Storage devices of computer hardware

Storage devices remember and store data (programs, documents, images) for short-term or long-term use. HDD (magnetic, high capacity): data on rotating platters; large capacity and low cost per GB; slower than SSD and sensitive to vibration; common in desktops and laptops. SSD (flash memory, no moving parts): uses NAND flash; faster, silent and lower power than an HDD; smaller and lighter; forms 2.5-inch SATA and M.2 NVMe. Optical disc (laser): CD (about 700 MB), DVD (4.7 GB), Blu-ray (about 25 GB); read and written by a laser; removable and inexpensive; used for software distribution, backup and media. USB flash drive (portable flash memory): NAND flash, USB interface, from a few GB to hundreds of GB, convenient for data transfer and backup. Magnetic tape (sequential access): data as magnetic signals on a long tape; very high capacity and very low cost per GB; used for long-term backup and archiving; sequential access is slower. Comparison table (HDD, SSD, optical, USB, tape): typical capacity 1 TB to 20 TB, 256 GB to 8 TB, 700 MB to 25 GB or more, 8 GB to 1 TB, several TB to hundreds of TB; moving parts yes, no, yes (disc rotation), no, yes (tape reel); speed slower, faster, moderate, fast, slow (sequential). Key takeaways: SSDs are faster and more reliable than HDDs; optical discs and USB drives are convenient for data distribution and backup; tape suits very large, long-term backup.

Slide 12: Processing device: the CPU

The CPU (central processing unit) is the electronic circuitry in a computer that carries out the instructions of a program; it is a small chip containing millions to billions of transistors. Internal structure: control unit (CU, controls the execution of instructions), arithmetic logic unit (ALU, arithmetic and logical operations), registers (for example program counter, instruction register, general-purpose registers), cache memory (very fast memory for frequently used data and instructions) and the system bus (data bus, address bus, control bus) to memory and other devices. Instruction cycle: 1 fetch, the CPU fetches an instruction from memory using the program counter; 2 decode, the control unit decodes it to understand the operation; 3 execute, the ALU performs the arithmetic or logical operation; 4 store (write back), the result is stored in a register or written to memory; then repeat for the next instruction. Role: input devices, CPU (processing), memory (RAM and storage), output devices. Key points: the CPU is the brain of the computer; it has CU, ALU, registers and cache; it executes billions of operations per second; it communicates with memory and I/O through system buses; modern CPUs have multiple cores.

Slide 13: Computer architecture

Computer architecture is a functional description of the requirements and design implementation for the various parts of a computer; it deals with the functional behaviour of a computer system. It defines how the major components (CPU, memory, I/O devices, storage) are organised and work together; it specifies the functions, interfaces, data flow and control flow among them; it provides the set of resources the hardware offers to software (instruction set, registers, memory model, I/O mechanisms); it focuses on what the system does (functional behaviour), not the detailed hardware implementation. Computer architecture = the set of resources provided by hardware for software. System bus: data bus (bidirectional), address bus (carries memory and I/O addresses), control bus (carries control signals), connecting the CPU (control unit, ALU, registers), main memory (RAM), I/O interfaces (keyboard, display, printer, mouse) and secondary storage (HDD, SSD, optical disc). Key takeaways: it defines the organisation and interconnection of components, specifies functions and interfaces visible to software, provides hardware resources and affects performance, cost and capability. Fetch-execute cycle: the CPU fetches an instruction from memory via the system bus; the control unit decodes it; the ALU performs the operation; the result is stored back to a register or memory or sent to an I/O device.

Slide 14: Computer system architecture

A computer system consists of a CPU, memory, input and output devices, and the buses that connect them. CPU: control unit, arithmetic logic unit and registers; it fetches, decodes and executes instructions and controls the whole system. A clock provides timing signals that synchronise all components. Main memory: ROM (read only memory; stores permanent data such as firmware or the boot program) and RAM (random access memory; stores data and instructions currently in use; volatile). I/O interface connects input devices (keyboard, mouse), output devices (monitor, printer) and secondary storage (HDD, SSD, CD/DVD) to the system bus. Buses: address bus (carries memory or I/O addresses, usually from the CPU to other devices), data bus (carries data between CPU, memory and I/O devices, in both directions), control bus (carries control signals such as read, write, interrupt, clock). Closing line: computer architecture = the set of resources provided by hardware for software.

Slide 15: Computer architecture: buses and a read from RAM

A bus is a common pathway through which information flows between components. Address bus: specifies the location (address) of memory or a device (unidirectional, usually CPU to others; for example 32 or 64 bits). Data bus: carries the actual data between devices (bidirectional; for example 8, 16, 32 or 64 bits). Control bus: provides timing and control signals (read, write, interrupt, clock, reset). The computer bus is a set of parallel wires (address, data and control buses) used to transfer information between components. The CPU connects over these buses to RAM (main memory), ROM (non-volatile memory), I/O devices (disk, USB, network) and other devices (timer, GPU). Example, the CPU reads data from RAM: 1 the CPU puts the address of the memory location on the address bus (for example 0x1000); 2 it asserts a control signal (Read) on the control bus; 3 the RAM receives the address and control signal and puts the data stored at that location on the data bus; 4 the CPU reads the data from the data bus. Key points: the address bus selects where to read or write; the data bus transfers the data; the control bus tells what operation to do and gives timing; all devices share the same buses.

Slide 16: Address bus

1 What is it: the address bus carries address information from the CPU to main memory or other devices; it is unidirectional (one-way, CPU to other devices); its width (number of lines) determines how many memory locations the CPU can address. 2 Example, a 32-bit address bus with lines A31 to A0: each line is 0 or 1; 32 lines give 2^32 different addresses; the CPU places an address on the bus and the selected memory or device responds (RAM, ROM, I/O device). 3 Address bus lines (32 bits): 32 parallel wires, each carrying one bit; together a 32-bit binary number that represents a memory location or device address. 4 Number of addressable locations = 2^n, n being the number of address lines; for n = 32, 2^32 = 4,294,967,296 (about 4 billion addresses), so a 32-bit address bus addresses locations 0 to 4,294,967,295. 5 Address range (32-bit): smallest address all 0s = 0 decimal; largest address all 1s = 4,294,967,295 decimal = 2^32 minus 1. Summary: the address bus is a unidirectional set of lines from the CPU to memory or other devices, and its width determines how many unique locations or devices can be addressed.

Slide 17: Data bus

The data bus carries data between the CPU, main memory and input/output devices. It carries the actual data (for example instructions, numbers, characters) to and from the CPU, main memory or any other device; it is bidirectional (two-way); the number of wires (bus width, for example 8, 16, 32 or 64 bits) decides how much data is carried at one time, and a wider bus transfers more data at once, improving performance. Example, an 8-bit data bus with lines D7 to D0 carries 8 bits at once, with values from 0000 0000 = 0 to 1111 1111 = 255 (0 to 255). It works together with the address bus and the control bus.

Slide 18: Control bus

The control bus carries control and timing signals the CPU uses to communicate with memory, I/O devices and peripherals; it does not carry actual data. Signals: READ (memory or I/O read), WRITE (memory or I/O write), INTERRUPT (interrupt request), CLOCK (system timing), and other control signals (reset, bus request and acknowledge, I/O or memory select, byte enable). The CPU (control unit, ALU, registers) generates control signals to coordinate all operations; memory (RAM read/write, ROM read), I/O devices (keyboard, mouse, network interface, sensors) and peripherals (monitor, printer, storage) are on the bus. Key points: it carries control and timing signals, not data; used by the CPU to coordinate memory, I/O and peripherals; typical signals READ, WRITE, INTERRUPT, CLOCK, RESET; works with the address and data buses; helps synchronise transfers. The three system buses: data bus carries the actual data (what); address bus carries the memory or I/O location (where); control bus carries control and timing signals (command and when).

Slide 19: Direct memory access (DMA): comparison with programmed I/O

DMA transfers data directly between I/O and memory without needing the CPU to move every byte. Block diagram: the CPU (control unit, ALU, registers) sends a DMA request and configuration (start address, count, read/write, device) to the DMA controller (address register, data register, data count, control logic); the controller and the CPU, main memory (RAM) and I/O device (for example a disk) share the system bus (address, data and control buses); at the end an interrupt tells the CPU the transfer is complete. 1 Programmed I/O (CPU-controlled transfer): the CPU issues I/O commands; the data goes through the CPU (it reads from the device and writes to memory); the CPU is busy for the entire transfer. 2 DMA: configure DMA (start address, count, read/write); the DMA controller transfers the data between the device and RAM; the CPU continues other work not involved in the transfer; an interrupt is raised when complete. Closing line: DMA improves performance by allowing high-speed transfers without continuous CPU intervention.

Slide 20: Direct memory access (DMA): operation, advantages and disadvantages

DMA lets an I/O device transfer data directly to or from main memory without the CPU moving each byte. The DMA controller has an address register, a data count register, a control register and control logic. How it works: 1 the CPU configures DMA, writing the start address, data count, read/write and the device to the DMA controller; 2 the DMA controller takes control of the bus and transfers data directly between the I/O device and main memory; 3 the CPU does other work and executes other instructions meanwhile; 4 when the transfer completes, the DMA controller notifies the CPU by an interrupt. Advantages: the CPU need not move each byte; faster transfer, especially for large blocks; the CPU can do other tasks, giving better system performance. Disadvantages: more complex hardware and control logic; needs careful coordination (bus arbitration); may cause a temporary delay for CPU access to the bus (bus contention).

Slide 21: Binary data representation

Each bit has a positional weight equal to a power of 2. The binary number 1000001 has bits (from left) 1 0 0 0 0 0 1 with weights 2^6 to 2^0, that is 64, 32, 16, 8, 4, 2, 1. Conversion: multiply each bit by its weight; only positions holding 1 contribute: 1 x 2^6 + 0 x 2^5 + 0 x 2^4 + 0 x 2^3 + 0 x 2^2 + 0 x 2^1 + 1 x 2^0 = 64 + 1 = 65, so 1000001 (base 2) = 65 (base 10). Key idea: moving one position to the left doubles the weight.

Slide 23: Data storage: memory hierarchy

Computer memory means the devices used to store data and programs. Basic memory hierarchy: permanent data storage (non-volatile) and temporary data storage (volatile). Input devices (mouse, keyboard, scanner, camera, microphone) create data that goes into the computer; permanent storage (hard drive, SSD, USB flash drive) saves data for a long time; temporary storage (RAM, cache) is used while running, and programs are loaded into memory. Data access hierarchy, from faster to slower: input devices; CPU registers (smallest, fastest); cache memory (small, very fast); RAM (main memory) with physical RAM and virtual memory on the hard drive (temporary storage, volatile); storage devices (secondary storage: HDD, SSD, USB drive, network storage; permanent storage, non-volatile); CPU at the slow end. Permanent storage keeps data even when power is off and holds the operating system, applications and user files; temporary storage keeps data only while the computer runs and is faster but loses data when power is off.

Slide 24: Cache memory

Cache memory is a small, very fast memory located close to the CPU; it stores frequently used data and instructions so the CPU can access them quickly. When the CPU requests data it first checks the cache: if found (cache hit) it is returned quickly; if not (cache miss) the data is fetched from the slower main memory (RAM) and a copy is stored in the cache. Diagram: CPU (registers, ALU, control unit), cache memory and main memory on a system bus with address and data buffers; word transfer between CPU and cache (for example 4 to 8 bytes, very fast, about 1 to 3 cycles) and block transfer between cache and main memory (for example 64 bytes, slower, about 50 to 100 cycles). Cache hierarchy: CPU, L1 cache (internal, fastest, 1 to 3 cycles), L2 cache (on chip, fast, about 5 to 10 cycles), a second box labelled L2 cache (on chip, less fast, about 20 to 40 cycles), main memory (RAM, slow, about 50 to 100 cycles); larger capacity but slower access time down the chain. Key points: much smaller than main memory but much faster; exploits locality of reference (recently and frequently used data); modern processors use L1, L2 and L3; cache is usually built from fast SRAM (static RAM). Advantages: reduces average memory access time; improves overall performance; lets the CPU run at high speed without waiting for slow main memory.

Slide 25: Data storage in a computer: primary and secondary storage

Computer memory storage divides into two groups. Primary storage is fast and directly accessed by the CPU (RAM and ROM): RAM (random access memory) is read and write, volatile (data lost when power is off) and very fast; ROM (read-only memory) is read only, non-volatile (keeps data without power) and stores firmware (for example BIOS/UEFI). Secondary storage (auxiliary memory) has lower speed and communicates indirectly with the CPU through main memory and the I/O controller (HDD, SSD, CD/DVD, USB flash drive, memory card); it has larger capacity, is slower than RAM, is non-volatile and stores the operating system, applications and user files. Key differences (primary versus secondary): speed fast versus slower; capacity smaller versus larger; access by CPU directly versus indirectly; volatility RAM volatile, ROM non-volatile versus non-volatile; main use data and instructions currently in use versus long-term storage. Why two types: RAM must be very fast so the CPU quickly reaches instructions and data; secondary storage gives large capacity at lower cost for long-term storage; programs and files are first loaded from secondary storage into RAM before the CPU can execute them. Example, running a program: 1 the program is stored on SSD/HDD; 2 the operating system loads it into RAM; 3 the CPU fetches instructions and data from RAM and executes them; 4 results can be saved back to SSD/HDD.

Slide 26: Types of computer memory: volatile and non-volatile

Slide 38: Von Neumann architecture (stored-program computer)

Von Neumann architecture is the stored-program computer concept in which instruction data and program data are stored in the same memory. Diagram: the CPU (microprocessor; control unit, ALU, registers PC, IR, general registers) is joined to a single main memory (the same memory for instructions and data: addresses 0000 to FFFF, instructions at the low addresses, data above) and to input/output (keyboard, monitor, disk/storage) through one address bus, one data bus and one control bus. Key idea: program instructions and data are stored together in the same memory; the CPU reads instructions just as it reads data; this simplifies the hardware and lets programs be stored, modified and executed easily. 1 CPU: fetches instructions and data from memory, decodes and executes them using registers, ALU and control unit. 2 Main memory (single memory): stores both instructions and data in one memory space; each location has an address and can hold an instruction or data. 3 I/O devices: exchange data with the CPU through the same buses. Example of memory contents: address 0000 content 3E 05 (instruction MOV A, 05H); 0002 content 06 03 (instruction MOV B, 03H); 0004 content 80 (instruction ADD A, B); 0005 content 0A (data value 0A); 0006 content 14 (data value 14). Closing line: the same memory stores both the program and the data, accessed using the same address, data and control buses.

Slide 39: Harvard architecture

Harvard architecture uses separate storage and signal pathways for instructions and data. Diagram: the CPU (control unit, ALU) connects to program memory (instructions; ROM/Flash) by an instruction address bus and an instruction data bus, and to data memory (data; RAM) by a data address bus and a data bus; I/O interfaces link input devices (sensors, switches, keyboard) and output devices (display, LEDs, actuators, motor). Parallel operation: the instruction path (from program memory) runs fetch instruction at address n, instruction available, execute instruction, next instruction at address n+1, while the data path (from and to data memory) runs read data at address x, data available, process data in the ALU, write data at address y, at the same time. Key idea: separate memories and buses for instructions and data; the CPU can fetch an instruction and access data at the same time; widely used in microcontrollers and many embedded microprocessors (for example ARM, PIC, AVR, dsPIC). Advantages: higher performance (parallel access to instruction and data); no bus contention; suitable for real-time and embedded systems. Disadvantages: more complex hardware; higher cost (more buses and memories). Comparison with Von Neumann: one memory and one bus for both instructions and data, versus separate memories and buses. Closing line: simultaneous instruction fetch and data access give higher performance.

Slide 40: Comparison of Von Neumann and Harvard architectures

Von Neumann (stored-program computer): instruction data and program data are in the same memory; one address bus, data bus and control bus. Harvard: instructions and data are in separate memories with separate buses (instruction address, data and control buses, and data address, data and control buses). Table. Memory organisation: a single memory for instructions and data, versus separate memories. Buses: one set of address, data and control buses, versus separate buses for instructions and data. Flexibility: high, memory space can be used for either instructions or data, versus limited, fixed memory size for instructions and for data. Speed: slower, because instructions and data share the same buses and cannot be accessed at the same time, versus faster, because instructions and data can be accessed simultaneously over separate buses. Examples: general-purpose computers (PCs), versus embedded systems, microcontrollers and DSPs (for example washing machines, automotive controllers). Summary: Von Neumann is simpler and more flexible, while Harvard is faster and better suited to embedded applications.

Slide 44: Stack in a microprocessor

The control unit maintains a stack in the CPU (using registers) or in main memory. A stack is like a tunnel closed at one end, so the last entry is the first out (LIFO, last in first out). Slide 50: Machine instruction cycle: fetch, execute, interrupt

The machine instruction cycle is the sequence of operations the CPU performs to fetch, decode, execute an instruction and handle interrupts, repeating for each instruction. 1 Fetch: read the next instruction from memory into the processor: the PC holds the address; the address is copied from the PC to the MAR and sent to memory; the instruction at that address is read into the MBR; it is transferred from the MBR to the IR; the PC is incremented to point to the next instruction. 2 Execute: interpret the opcode and perform the operation: the control unit decodes the instruction in the IR; required data is fetched from registers or memory; the ALU (and other functional units) performs the arithmetic, logic, data transfer or I/O operation; the result is stored in a register, memory or I/O device; example ADD R1, R2 means R1 gets R1 + R2 (performed by the ALU). 3 Interrupt: if interrupts are enabled and one has occurred, save the current state and service it: after each instruction the CPU checks for pending interrupts; if one is detected the current state (PC, registers, flags) is saved on the stack; the CPU branches to the interrupt service routine (ISR); after the ISR finishes, the previous state is restored and normal execution resumes with the next instruction. Flow: start, fetch, execute, interrupt pending? yes, service interrupt, no, next instruction. Example fetch cycle: PC = 2000, copied to MAR = 2000, memory shows 2000 ADD R1, R2; 2001 SUB R3, R4; 2002 LOAD R5, the instruction goes over the data bus to MBR then IR (both ADD R1, R2) and the PC becomes 2001.

Slide 51: CPU operation: fetch, decode, execute

The CPU repeatedly performs the fetch, decode, execute cycle to run a program. Instruction cycle (five steps): 1 fetch instruction (read from memory): the PC holds the address of the next instruction (for example 0x04), the address is copied to the MAR and sent to memory on the address bus, the instruction is read from memory into the MBR and copied to the IR (for example ADD R1, R2); 2 decode instruction (interpret meaning): the control unit decodes the instruction in the IR, determines the operation (for example ADD) and which operands are needed (R1 and R2), and generates control signals to fetch operands and control the ALU and other units; 3 execute (perform operation): the ALU performs the operation (R1 + R2), taking operands from registers or memory; the result is stored in a register (for example R1) or prepared for writing to memory; 4 access memory (if needed): for instructions such as LOAD or STORE the CPU uses the MAR and MBR to read from or write to memory over the data bus under control signals; 5 update registers / PC (next instruction): the PC is automatically updated to point to the next instruction (for example 0x05), other registers may also be updated with the result. Example state: PC = 0x04, MAR = 0x04, IR = ADD R1, R2, MBR = ADD R1, R2; memory 0x00 MOV R1, 5; 0x01 MOV R2, 3; 0x02 SUB R1, R2; 0x03 JMP 0x08; 0x04 ADD R1, R2; 0x05 STORE R1, 0x10. Closing line: this cycle repeats for every instruction, letting the CPU execute a program step by step.
